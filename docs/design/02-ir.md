# 02 — IR

The IR is the compiler's only middle representation. It is structured. A function body is a tree of regions, not a control-flow graph of blocks and gotos. Wasm is structured in the same way, so codegen is a walk, and the relooper wasm3 wrote (`docs/wasm3-study/02-runtime-and-abi.md`) is not on this path.

The IR is also not SSA. Go's SSA discards the nesting this compiler needs to keep, and it assumes values live in registers. wasm3 then disabled register allocation and assigned one Wasm local per SSA value anyway. Here a mutable local is created when the Go program has a variable, and a temporary exists only inside one straight-line stretch, where it can stay on the Wasm operand stack if it is used once.

Two instruction layers share one data structure. The **high** layer names Go operations (`slice.append`, `map.get`, `iface.call`, `go`). Passes rewrite those away. The **low** layer is what codegen accepts: each instruction is one Wasm instruction, or a short sequence the emitter owns (`call`, `struct.get`, `br`). A verifier flag, `low`, is false until the runtime-lowering pass and true after it. Codegen refuses a module that is not `low`.

## Types

IR types are the Wasm types of `03-type-mapping.md`, plus a high-level form used before runtime lowering. The high-level form is a `go/types.Type` pointer. The low form is one of:

| IR type | Wasm |
|---|---|
| `i32` `i64` `f32` `f64` | the scalar |
| `ref T` | `(ref T)`, non-null |
| `refnull T` | `(ref null T)` |
| `exn` | `exnref` |
| `extern` | `externref` |
| `funcref S` | `(ref S)` where `S` is a function type |

`i8` and `i16` appear only as the element of an array type, never as a value. A load of a packed element sign- or zero-extends to `i32`, which is what `array.get_s` / `array.get_u` do. There is no IR `v128`.

A struct type and an array type are interned. Two Go types that lower to the same shape share one IR type when `03-type-mapping.md` says they do (a named `type I int32` is the same Wasm type as `int32`). Identity of a Go named type for type assertions lives in the type descriptor, not in a distinct Wasm type.

## Values

A **var** is a function-scoped mutable slot. It becomes one Wasm local. Parameters are vars. A Go variable is a var of its lowered type. A var's type does not change.

A **temp** (`%t`) is a single-assignment name produced by an instruction. The verifier requires every use of a temp to be inside the same straight-line region that defined it, in an instruction dominated by the definition in that region. A temp does not survive a region boundary, a call, or a second use that the emitter cannot keep on the stack. The lowering pass inserts a var when a value must survive. This is the `OnWasmStack` idea from wasm3 (`docs/wasm3-study/02-runtime-and-abi.md`) without an SSA scheduler.

There are no phi nodes. A value that flows out of an `if` is written to a var in each arm.

## Regions

```
Region =
  | seq   []Stmt
  | block { name, params []Var, results []Type, body Region }
  | loop  { name, body Region }
  | if    { cond Temp, then Region, else Region }
  | switch { tag Temp, cases []Case, default Region }   // low: br_table
  | try   { body Region, tag Tag, params []Var, handler Region }
  | dispatch { state Var, arms []Region }               // irreducible goto only
```

`block` and `loop` are Wasm `block` and `loop`. A `br` names one of them. `br` to a `block` exits it with the block's results. `br` to a `loop` restarts it. `if` is Wasm `if`/`else`/`end`. `try` is `try_table` with one `catch_ref` whose target is a sibling block the emitter creates; the handler region's params are the tag's payload and an `exn`. The prototype in `prototypes/eh-panic/panic.wat` is the shape the emitter copies, including the rule that `catch_all` pushes no operands.

`dispatch` exists for one reason, below. It is not available to the AST lowerer except through the goto pass.

Statements are assignments, stores, calls that return nothing, `br`, `br_if`, `return`, `unreachable`, and region statements. An expression is an instruction that produces a temp.

`call_indirect` is not in v1. Every indirect call is a `call_ref` on a funcref stored in a struct. That is the wasm3 phase-D dispatch (`docs/wasm3-study/01-type-mapping.md`) made the only dispatch.

Saturating truncations (`i32.trunc_sat_f32_s` and the rest) implement the Go conversions from float to integer, which are implementation-defined out of range; we match `GOARCH=wasm` and truncate-saturate.

## Lowering from the AST

The lowerer walks a type-checked `go/ast` body. It does not build a CFG.

### Expressions

Scalars lower to the numeric opcode. A sub-32-bit integer (`int8`, `int16`, `byte`, `bool`) is an `i32` in a var, and the lowerer masks or sign-extends at a store to a packed array and at a conversion. `bool` is `0` or `1`.

Short-circuit `&&` and `||` are `if` regions, so the right operand is not evaluated early. This is why expressions are not a pure tree: a short-circuit expression is a statement that writes a var.

A call is `call` for a known function and `call_ref` for a func value. Multi-value is a Wasm multi-value; the temps are the results in order. A call that may park is still an ordinary call. The callee saves and restores `$g` (`04-runtime-and-abi.md`). The caller does not.

Composite literals of structs and arrays are `struct.new` / `array.new_fixed` for small arrays and `array.new_default` plus a loop of sets for large ones. The cutoff is 16 elements, matching a code-size choice rather than an engine limit (`array.new_fixed` is limited to 10,000 operands by V8, `kV8MaxWasmArrayNewFixedLength`).

Addressing and dereference follow `03-type-mapping.md`. After the escape pass, a non-escaping `&x.f` is the `struct.get` / `struct.set` of `x`, and the pointer var is gone.

### Statements

| Go | IR |
|---|---|
| `if` / `else` | `if` region. The condition is a temp of type `i32`. |
| `for cond { }` | `loop` containing an `if` that `br`s to the surrounding `block` when the condition is false. |
| `for { }` | `loop`. |
| `for i := 0; i < n; i++` | init in the enclosing seq, then the `for cond` shape, with the post statement at the bottom of the body. |
| `for range` over slice, array, string, integer | a `loop` and an index var. The iteration variable is a new var per iteration when its address escapes (Go 1.22 semantics); otherwise it is one var assigned each iteration. |
| `for range` over a map | `map.iter`, then a loop that calls `map.next` until it returns false. The iterator holds the table snapshot from `04`. |
| `for range` over a function | a loop whose body is the yield. `break`, `return`, and `goto` out of the body `throw` a private tag `$go.rangeExit` that the loop's `try` catches. A yield that returns false and an iterator that calls yield again panics with the Go 1.22 message. This is the same control transfer `cmd/compile` does with a panic, done with a tag so it is not a user-visible `panic`. |
| `switch` on a value | a chain of `if`s, or a `switch` region when the tag is an integer and the case set is a dense range no wider than 4× the number of cases. `fallthrough` is a `br` to the next case's block. |
| `switch` on a type | `type.switch`, then a `switch` on the resulting index. |
| `select` | one `select` instruction. It is not a `switch`. The runtime pass expands it. |
| `break` / `continue` | `br` to the `block` or `loop` the label names. An unlabeled `break` targets the innermost loop, switch, or select. |
| labeled statement | a `block` with that name wrapped around the statement. |
| `return` | evaluate results, run the frame's defers (a call the defer pass inserts), `return`. |
| `defer` | evaluate the arguments, build the closure, push it on the frame's defer var. |
| `go` | build the closure, call `runtime.go` with it. |
| assignment | `local.set`, or `store` through a pointer, or a struct/array field set. A two-result map or type assert writes both vars. |
| `++` / `--` | load, add, store. |

### `goto`

Most functions never use `goto`. The lowerer handles the ones that do as follows.

1. Each label becomes a `block` whose body is the source from that label to the next label in layout order, if that range contains no jump into it from outside. Forward `goto` is `br` out to that block's end, which is the standard "block per label, branch outward" encoding and needs no relooper.
2. A backward `goto` to a label that dominates the jump in the AST nesting becomes a `loop` around that range and a `br` to the loop.
3. If a jump enters a loop body from outside it, or two loops jump into each other, the function's body from the first such label to the end is one `dispatch` region. Each label in that range is an arm. A `goto` stores the target arm's index in the state var and `br`s to the dispatch loop. Codegen emits:

```wat
(loop $d
  (br_table $arm0 $arm1 $arm2 (local.get $state))
)
```

with each arm in a `block` so it can exit the loop or set the state and branch back. This is the fallback wasm3 used when its relooper bailed (`docs/wasm3-study/02-runtime-and-abi.md`), restricted to the function that needs it. The IR verifier checks that a function contains either structured branches or one `dispatch`, not a mix of `dispatch` and a `goto` it did not classify.

Go's rule that `goto` cannot jump over a variable declaration is enforced by `go/types` before we see the function.

### Defer and panic in the IR

The defer pass, which runs as part of runtime lowering, rewrites a function that contains `defer` or that must recover:

- Allocate `var defers refnull $go.defer` and, if the function's body can observe a panic, wrap the body in `try` of `$go.panic`.
- `defer` becomes a push onto `defers`.
- On the normal edge, call `runtime.deferRun(defers)` then produce the results.
- The handler calls `runtime.deferRun(defers)` and then either `return`s (the panic was recovered) or `throw_ref`s. The flag lives on the panic object (`04-runtime-and-abi.md`).

A function with no defer and no recover has no `try`. The exception propagates. The prototype `prototypes/eh-panic` runs this pattern: a frame without `try_table` lets the exception through, `throw_ref` rethrows the same `exnref`, and skipping the rethrow is the recover.

## Calls and the ABI, as the IR sees them

A function signature in the IR is the Wasm signature. Parameters and results are already lowered types: one `i32` for an `int`, one non-null `ref $go.string` for a string, one `refnull` for a slice, one ref for a struct, one ref for an array. Nothing is flattened into leaf scalars. wasm3 kept a second "flat" ABI because the Go register ABI counted leaves (`docs/wasm3-study/01-type-mapping.md`). This compiler has no register ABI.

The first parameter of a closure body and of a method value is the closure ref. A method's first parameter is the receiver. An interface method's funcref has the same signature as the concrete method, with the receiver already the data word's type, or `refnull any` plus a `ref.cast` in a wrapper when the concrete receivers differ. Wrappers are generated per `(interface, concrete, method)` and interned.

Multi-value results are the Wasm result list. There is no result area in memory.

## Text format

The text format is the stable test input and the `dump-ir` output. The printer is deterministic: vars are named from the source when they have a name, temps are `%0`, `%1` in emission order, regions are indented two spaces. The grammar below is the contract that stream C publishes for stream D (`09-bootstrap-plan.md`): `parse(print(x)) == x`, enforced by `internal/ir` tests.

```
func main.fib(n i32) i32 {
  var r i32
  if i32.lt_u n, 2 {
    r = n
  } else {
    %0 = call main.fib(i32.sub n, 1)
    %1 = call main.fib(i32.sub n, 2)
    r = i32.add %0, %1
  }
  return r
}
```

### Grammar

Lexical tokens: identifiers (`main.fib`, `$go.string`, `i32.add`), temps (`%0`), integers, floats, string literals (`"..."` with `\n` `\t` `\r` `\"` `\\` `\xHH`), and punctuation `{ } ( ) , : =`. Line comments start with `//`. Identifiers may contain `.`, `$`, `_`, `/`, `*`, `-`.

```
file       = { decl }
decl       = "low"
           | typeDecl | globalDecl | dataDecl | funcDecl

typeDecl   = "type" id [ "sub" id ] typeBody
typeBody   = "struct" "{" { [ "mut" ] id type } "}"
           | "array" [ "mut" ] type
           | "func" "(" [ type { "," type } ] ")" { type { "," type } }

globalDecl = "global" [ "mut" ] id type [ "=" expr ]
dataDecl   = "data" id stringlit

funcDecl   = "func" [ "export" stringlit ] id
             "(" [ param { "," param } ] ")" { type { "," type } } region
param      = id type

region     = "{" { stmt } "}"

stmt       = region
           | "var" id type
           | dest { "," dest } "=" expr
           | expr                                 // side-effecting call / store
           | "return" [ expr { "," expr } ]
           | "br" id [ expr { "," expr } ]
           | "br_if" id expr [ "," expr { "," expr } ]
           | "unreachable"
           | "if" expr region [ "else" region ]
           | "loop" id region
           | "block" id region
           | "switch" expr "{"
                 { "case" int ":" region }
                 [ "default" ":" region ]
             "}"
           | "try" [ id ] region
             "catch" id [ "(" param { "," param } ")" ] region
           | "dispatch" id [ "(" id ")" ] "{"
                 { "arm" int ":" region }
             "}"

dest       = id | temp                            // var or %t

expr       = temp | id | int | float | stringlit
           | "call" id "(" [ expr { "," expr } ] ")"
           | "call_ref" typeImm expr { expr }
           | "string" stringlit                   // high: string header from literal
           | op typeImm* fieldImm? dataImm? labelImm? [ expr { "," expr } ]

type       = numType | "exn" | "extern"
           | "ref" heapType | "refnull" heapType
           | "go." id                             // high-level Go type placeholder
numType    = "i8" | "i16" | "i32" | "i64" | "f32" | "f64"
heapType   = "any" | "eq" | "i31" | "struct" | "array"
           | "none" | "nofunc" | "noextern" | "func" | id

typeImm    = type | id                            // heap / defined-type name for ops
```

`op` is an instruction name from the tables above (`i32.add`, `struct.get`, `map.get`, …). Ops with type immediates write them before value operands: `struct.get $Point X p`, `ref.null $go.string`, `array.new_data $go.bytes $lit`, `map.make go.K go.V hint`. `i32.const` / `i64.const` / `f32.const` / `f64.const` take a numeric immediate; a bare integer in expr position is an `i32` constant.

A leading `low` declaration marks the module as past runtime lowering. Codegen refuses a module that is not `low`. The verifier rejects any high-level op in a `low` module.

The parser is `ir.Parse` in `internal/ir`. The verifier rejects a temp used across a region boundary (temps are scoped to one straight-line `seq`). Golden tests under `internal/ir/testdata/` compare printer output to checked-in files; `-update` refreshes them. Hand-written targets for the lowerer: `empty_main.ir`, `println.ir`, `fib.ir`.

A high-level fragment, the kind `dump-ir` shows before runtime lowering:

```
func main.main() {
  %0 = string "hello"
  call runtime.printstring(%0)
  call runtime.printnl()
  return
}
```

## What codegen does with a region

```
seq        walk the statements
block N    wasm block, body, end. br N is br to that depth.
loop N     wasm loop. the body ends with br N for a continue that fell off.
if         wasm if, then, else, end. the condition is an i32 on the stack.
switch     br_table when the verifier marked it dense, otherwise a chain of
           ifs the switch-build pass already produced. codegen does not
           invent the chain.
try        the block nesting in prototypes/eh-panic/panic.wat
dispatch   loop { br_table arms }
```

Branch depths are computed by the walk, from the inside out, and stored on the `br` instruction before bytes are written. A `br` whose target is not an ancestor is a verifier error. That error is how a bad goto classification fails in a test instead of in V8.

## Pass order, again, as IR rewrites

The passes in `01-architecture.md` are IR-to-IR. None of them builds a graph of basic blocks. Escape analysis is a walk that marks vars whose address is stored, returned, or passed to another function, then rewrites. Inlining substitutes a region tree and renames vars. Dead code is a reachability mark from the exported roots and from live itables, then a deletion of unmarked functions and of struct types with no remaining `struct.new`.

The IR never represents a linear Go stack, a PC block id, or an unwind flag. wasm3's ABI comment records those as the `GOARCH=wasm` calling convention it deleted (`docs/wasm3-study/02-runtime-and-abi.md`). They are not waiting to be added back.
